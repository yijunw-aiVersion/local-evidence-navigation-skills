# 原文理解与支持强度

## 先匹配问题所问的对象与层级

| 用户在问 | 能直接支持的原文 | 仍不能推导 |
|---|---|---|
| 是否做过某动作 | 明确主体、动作和同一对象的陈述 | 规模、独立完成或完整方法 |
| 某个机制如何实现 | 具体关系、操作、条件或控制路径 | 未描述的其他阶段与全流程 |
| 完整流程如何工作 | 必要阶段及阶段间关系、边界/结束条件 | 靠邻近主题自动补齐缺失步骤 |
| 结果或指标是否成立 | 指标定义、对象、条件、测量和来源 | 把目标当结果、把局部结果推广到其他项目 |

证据要求来自用户问题，不从期望答案反推。明确“构建测试集”的自述直接支持该行为；没有标注协议可限制方法回答，但不能因此写成“没有构建证据”。“搭建评估系统”“准确率提升”是相邻事实，不能单独证明构建测试集。

## 每次只检查会改变答案的差异

引用前核对主体、本人/团队、动作对象、项目、时间、适用条件、否定/例外。时间只有影响原问题时才深入；不从模糊年份推算资历。不能要求每次查齐所有维度。

若一个取消机制片段只描述消息传递，它支持消息机制；不能补出资源回收、回滚、端到端传播或硬/软取消。若项目有实验方法，它可能加强验证经历的说明，不自动证明其他领域适配。

原文表格错位、来源身份或指标归属不清时，回到邻近标题/表头/正文核对，保留可靠部分，并限制歧义片段；不能否定整份来源。摘要中的作者数、对象归属或结论都要回原文确认。

## 三种支持关系

- **used：直接支持。** 当前原文明确支持该问题项判断，结论保留自述/测试范围。
- **limited：相关上下文。** 有助于解释主题、范围或限制，但不是该具体判断的直接证据。
- **not_used：未采用。** 与问题无关、重复无增益或经核对不能支持当前结论。

支持强度按问题项判断，不给来源打永久标签。已召回但未读正文为未核验，不能给它直接支持或“纯背景”结论。

## 早期证据、冲突与综合

综合前读取所有相关已保存原文。后读章节没有提到某事，不抵消早期肯定陈述；旧 Agent 的 limitation、subject 或停止理由也不是新证据。

出现相反原文时先核对版本、主体、项目、时间和条件。明确修订同一事实可更新当前结论，但保留旧版历史；无法解释的同条件冲突保留双方，说明未解决。不能以最后阅读、排名更高或摘要更流畅作为定案理由。

一段可以支持动作存在而不足以支持方法完整。对完整流程，只报告已证实阶段及其关系；多个机制片段如果没有连通关系证据，不能合成一次连续执行过程。短引文来自不同位置时分别引用，不能拼接成一条“原文”。

负面判断要用“在已读的 X/Y 节没有看到 Z”，避免“该来源没有 Z”。未召回、已召回未读、入口失败、OCR 丢失和原文矛盾分别报告。边界不能为了显得谨慎而改写已经明确支持的事实。
