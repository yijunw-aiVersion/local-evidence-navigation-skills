# 可选 Harness 流程契约

仅当环境实际提供阶段控制、原文记录和提交工具时适用。普通文件工具或 MCP 不自动具有这些工具；本包没有实现控制器。

## 阶段与语义

| 阶段 | Agent 行为 | 环境可能负责的能力 |
|---|---|---|
| exploring | 读取真实入口，按缺口选下一位置 | 工具范围、来源根和预算准入 |
| recording | 保存刚读原文，再决定补读/综合/停止 | 恢复精确引用、定位和持久 ID |
| ready_to_answer | 复核所有记录，按当前提交入口给答案 | 结构、覆盖项、ID 和分类检查 |
| answered / stopped | 尊重已结束状态；保留范围和缺口 | 保存结果、停止原因与历史计量 |

工具名与字段始终以当前 schema 为准；下面是既有契约的映射例子，不要求新环境实现完全相同 API。

## 记录与下一步

若提供 `record_evidence`，使用真实 source_id、问题项和工具要求的 quote_line/locator。由控制器恢复原文时，不自行造行号、复制错版引用或用摘要代替。quote_line 是对已缓存原文视图的选择，不意味着底层 read 新增行范围能力。

先保存合法记录，再选择 `next_read / submit / stop`。next_read 对应真实 target、轮次、missing、原问题项和关联 evidence_ids；同次调用局部 ID 与持久 ID 按实际回执替换。

submit 只安排综合时，不在记录参数里夹带最终答案。下一步参数失败不一定撤销已成功保存的证据；查看回执后续用已有 ID。已知格式错误按反馈修复，未知结果不能盲目重发。

## 综合映射

提供 submit_answer 时使用真实工具；要求直接 JSON 时给指定 schema。复核每个已保存 ID，覆盖每个原问题项；只有对该项直接支持的证据进入其支持列表。

本包的 per_aspect 复核可以映射到控制器的单条 disposition。若控制器不支持多问题项分类，按其真实结构拆分关联或在 reason 说明问题项范围，不偷偷新增字段。默认模板与外部 schema 不同的地方写入任务 profile。

## 预算与恢复

控制器可以限制累计输入、单次窗口、结果大小、阅读额度、模型批次、工具调用和输出预留。先确认计量单位：UTF-8 字节保守单位不等于 tokenizer token 或费用硬上限。软提示不会制造 controller 的硬限制。

恢复保持 task_id、账本、已用轮次/调用和实际费用；模型上下文压缩不返还额度。记录与最终综合同样需要剩余模型批次。来源版本改变时不得覆盖历史原文。

控制器能验证顺序、ID 和预算，不能证明语义判断正确、选择最优或来源齐全。对接先验证直接回答、一次局部补读、记录后错误恢复和限定停止，不能把安装通过当成行为通过。
